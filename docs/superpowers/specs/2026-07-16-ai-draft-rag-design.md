# AI 招聘草稿与 RAG 知识库设计

## 目标

在现有本地 BOSS 聊天系统中增加辅助式 AI 客服：系统读取当前打开会话中的候选人新消息，检索招聘知识库并调用 Kimi 生成短回复草稿。草稿必须经过人工采用、编辑和点击发送，系统不得自动发送。

## 范围

- 使用 Kimi 官方 OpenAI 兼容 Chat Completions API 生成草稿。
- 从 `C:\Users\81591\Desktop\kimi-keys.txt` 逐个验证 Key，仅保存第一个可用 Key。
- Key 写入本机 `.env`，不进入前端、日志、知识库或测试输出。
- 导入 AIHR 项目的 30 条招聘话术种子。
- 提供知识条目的新增、编辑、启用、停用和删除能力。
- 为当前打开会话中的候选人新消息自动生成一次草稿。
- 提供采用草稿、重新生成和忽略操作；采用只填入输入框。

不包含自动发送、批量回复、自动切换 BOSS 联系人、验证码处理、风控规避、多账号和完整 Chatwoot/Rasa 部署。

## 架构

保留 FastAPI、原生 JavaScript 和 DrissionPage。新增两个聚焦模块：

- `app/knowledge.py`：SQLite 知识库、话术导入、中文检索。
- `app/ai.py`：Kimi 调用、提示词构建、草稿清洗和质量检查。

继续由 `app/main.py` 提供 API，由当前页面展示草稿和知识库管理界面。SQLite 数据库存放在项目 `data` 目录；密钥从 `.env` 加载。

## RAG 检索

知识条目包含标题、正文、关键词、状态和更新时间。初始数据由 AIHR 的 30 条招聘话术拆成独立条目，并增加以下人工处理规则：

- 信息不足或知识冲突
- 薪资谈判和越权承诺
- 岗位暂停、满员或信息变化
- 隐私和联系方式
- 明确拒绝、骚扰或无关内容

检索采用本地中文字符片段、关键词和标题加权，不引入 Milvus、LangChain、Rasa 或本地向量模型。当前知识库规模较小，逐条评分简单、可测试且无额外内存占用。每次最多向 Kimi 提供 4 条最相关知识；低于置信阈值时标记为需要人工处理。

## 草稿生成

输入包含当前岗位、最近最多 8 条文本消息、候选人最新消息和检索到的知识。提示词要求：

- 只输出可发送的中文回复，不解释过程。
- 目标 15 至 60 个汉字，最多两句话。
- 一次最多提出一个问题。
- 不使用 Markdown、项目符号和客服套话。
- 不复述候选人的整句话。
- 不虚构薪资、地点、福利、名额或录用结果。
- 不确定时简短询问或标记人工处理。

本地质量检查拒绝空内容、超长、多问题、Markdown、变量占位符和常见 AI 套话。第一次不合格时允许 Kimi 压缩重写一次；仍不合格则只展示“需要人工处理”，不生成可采用草稿。

## 人工审核

AI 草稿显示在输入框上方，并展示“AI 草稿，发送前请审核”、匹配知识标题和状态。点击“采用”只把内容放入输入框，用户仍可修改；只有现有发送按钮会触发 BOSS 写操作。切换联系人、消息变化或忽略草稿时，不得误用旧草稿。

系统仅为当前已打开的会话生成草稿。为了避免 BOSS 风控，不自动点击或轮询切换其他联系人。

## 错误处理

- Kimi 未配置、Key 失效、余额不足或限流：显示明确错误，人工输入继续可用。
- RAG 无匹配：标记低置信度并建议人工处理。
- BOSS 出现安全验证：沿用现有全局暂停逻辑。
- Kimi 请求不自动无限重试；用户可手动重新生成。
- AI 生成失败不得影响现有聊天读取和人工发送。

## 验证

- 单元测试验证话术导入、中文检索、低置信度、草稿去重和质量检查。
- 使用假 Kimi 客户端验证 API，不消耗真实额度。
- 使用 Key 文件做一次只读模型列表请求和一条最短草稿请求，输出中隐藏 Key。
- 运行现有测试、JavaScript 语法检查和本地页面检查。
- 不通过自动化向 BOSS 发送测试消息。

## 验收标准

1. 可用 Kimi Key 被安全加载，前端和日志看不到密钥。
2. 候选人新消息能产生一条简短自然草稿，并显示检索依据。
3. AI 草稿不能绕过人工采用和发送按钮。
4. 知识条目可管理，30 条种子可检索。
5. Kimi 或 RAG 故障时，原有人工聊天功能不受影响。
